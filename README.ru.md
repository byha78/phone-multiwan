# phone-multiwan

Служба для Linux, которая распределяет соединения сразу по нескольким каналам раздачи интернета с одного телефона:

- **USB кабель** — телефон в режиме USB-модема;
- **LAN** — роутер, который берёт интернет с точки доступа телефона;
- **Wi‑Fi адаптер** — подключён к точке доступа телефона напрямую.

Зачем: у каждого способа раздачи свой предел. USB 2.0 + RNDIS дают ~300 Мбит/с, Wi‑Fi‑раздача телефона — ~145–160 на всех клиентов, роутер с портами 10/100 — ~98. Сотовая сеть при этом может давать больше. У автора 5G-телефон получал ~450 Мбит/с: через один роутер компьютер видел 96–98, а через три канала сразу — 456 по speedtest.

Полный разбор с замерами: [статья на Хабре](https://habr.com/ru/articles/1105562/), копия в репозитории: [docs/article.ru.md](docs/article.ru.md).

## Как это работает

```
                     ┌── USB кабель, режим USB-модема ───────────── ~300 ──┐
 5G ~450 ──► телефон ├── Wi‑Fi ──► роутер (WISP) ──► LAN-кабель ──── ~98 ──┼──► Linux: ECMP ──► программы
                     └── Wi‑Fi ──► USB Wi‑Fi адаптер ─────────────── ~50 ──┘
```

- Ставит общий маршрут по умолчанию с несколькими направлениями (ECMP). Хеш по адресам и портам раскладывает **соединения** по каналам: одно соединение идёт по одному каналу, многопоточная загрузка — по всем.
- Раз в 5 секунд проверяет интернет через каждый канал, исключает неработающий и возвращает ожившего.
- Маршрут службы стоит поверх маршрутов NetworkManager и убирается при остановке.
- Если Wi‑Fi адаптер после возвращения телефона застрял на низкой скорости, один раз переподключает его.

## Что нужно

- Linux с **NetworkManager**, `iproute2`, `iw`, `ping`, systemd.
- Телефон в режиме **USB-модема**: Android (`rndis_host`, `cdc_ncm`, `cdc_ether`) или iPhone (`ipheth`).
- Хотя бы ещё один канал с того же телефона: LAN через роутер и/или Wi‑Fi адаптер. Работает с любым набором из двух или трёх каналов.

## Установка

```bash
git clone https://github.com/byha78/phone-multiwan.git
cd phone-multiwan
sudo bash install.sh
```

Установщик копирует службу в `/usr/local/sbin`, включает её автозапуск и задаёт две настройки ядра в `/etc/sysctl.d/90-multiwan.conf`.

Рекомендуется подготовить NetworkManager:

```bash
# без этого IPv6-трафик пойдёт мимо балансировки
nmcli con modify "<профиль USB-модема>"     ipv6.method disabled
nmcli con modify "<профиль Wi‑Fi адаптера>" ipv6.method disabled
# LAN приоритетнее Wi‑Fi, если служба остановлена
nmcli con modify "<профиль LAN>" ipv4.route-metric 500
```

## Проверка

```bash
journalctl -u multiwan-balance -f      # «Active: USB, LAN, Wi-Fi»
ip route show default proto 99         # общий маршрут и веса каналов
```

## Настройка

Интерфейсы находятся сами: USB-модем — по драйверу, LAN — первый проводной интерфейс со шлюзом, Wi‑Fi — первый беспроводной. Если USB-сетевая карта на `cdc_ether` принимается за телефон, укажите `USB_IF` явно.

Параметры задаются без правки скрипта:

```bash
sudo systemctl edit multiwan-balance
```
```ini
[Service]
Environment=WIFI_MODE=reserve
Environment=USB_WEIGHT=3
```

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `USB_IF` / `LAN_IF` / `WIFI_IF` | определяются сами | явно указать интерфейсы |
| `USB_DRIVERS` | `rndis_host cdc_ncm cdc_ether ipheth` | драйверы для поиска USB-модема |
| `WIFI_MODE` | `balance` | `balance` — Wi‑Fi третий канал; `reserve` — только если не работают USB и LAN |
| `USB_WEIGHT` / `LAN_WEIGHT` / `WIFI_WEIGHT` | 2 / 1 / 1 | доля новых соединений на канале |
| `TARGETS` | `1.1.1.1 8.8.8.8` | куда пинговать при проверке |
| `PING_TIMEOUT` | 4 | ожидание ответа, секунды |
| `INTERVAL` | 5 | период проверки, секунды |
| `FAILS_TO_DOWN` | 3 | неудачных проверок подряд до исключения канала |
| `REFRESH_SIGNAL` | −60 | сигнал (dBm), при котором вернувшийся Wi‑Fi адаптер переподключается |
| `REFRESH_CHECKS` | 3 | хороших проверок подряд перед переподключением |

С Wi‑Fi в балансировке загрузка максимальна, а отдача немного ниже. Если отдача важнее, поставьте `WIFI_MODE=reserve`.

## Удаление

```bash
sudo systemctl disable --now multiwan-balance
sudo rm /usr/local/sbin/multiwan-balance /etc/systemd/system/multiwan-balance.service /etc/sysctl.d/90-multiwan.conf
```

## Ограничения

- Складывается загрузка в несколько потоков. Одно соединение ограничено своим каналом.
- Отдача не складывается: её ограничивает сотовая сеть.
- Выше скорости сотовой сети сумма не поднимется.
