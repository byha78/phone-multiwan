# phone-multiwan

**Как выжать из одного 5G-телефона всю скорость оператора, если каждый способ раздачи упирается в свой потолок.**

Телефон получает от оператора ~450 Мбит/с, но раздать их одним способом не получается: USB-модем упирается в USB 2.0 (~300), Wi‑Fi‑раздача телефона — в общий эфир одной точки доступа (~145–160 на всех клиентов), роутер — в свои 100-мегабитные порты (~98). Пока сумма этих потолков меньше скорости сотовой сети, каналы **складываются**. Этот репозиторий — небольшая служба для Linux, которая распределяет соединения по всем каналам одного телефона сразу.

| Схема | Speedtest, загрузка |
|---|---|
| Только роутер | 96–98 Мбит/с |
| USB-модем + роутер | 396 Мбит/с |
| **USB-модем + роутер + Wi‑Fi адаптер** | **456 Мбит/с** (отдача 48) |

Полный разбор с замерами: [docs/article.ru.md](docs/article.ru.md).

## Как это устроено

```
                     ┌── USB-кабель, режим USB-модема ───────────── ~300 ──┐
 5G ~450 ──► телефон ├── Wi‑Fi ──► роутер (WISP) ──► LAN-кабель ──── ~98 ──┼──► Linux: ECMP ──► программы
                     └── Wi‑Fi ──► USB Wi‑Fi адаптер ─────────────── ~50 ──┘
```

- В системе ставится общий маршрут по умолчанию с несколькими направлениями (ECMP). Хеш по адресам и портам (`fib_multipath_hash_policy=1`) раскладывает **соединения** по каналам: каждое соединение целиком идёт по одному каналу, а многопоточная загрузка — по всем сразу.
- Все каналы выходят в интернет через один телефон, поэтому внешний IP у всех соединений один, и сайты не видят «прыжков» между адресами.
- Служба раз в 5 секунд проверяет интернет через каждый канал, исключает неработающий и возвращает ожившего. Её маршрут стоит поверх маршрутов NetworkManager (metric 50), а при остановке убирается, и всё возвращается как было.
- Если телефон унесли и вернули, Wi‑Fi адаптер часто переподключается на краю зоны и остаётся на пониженной скорости. Служба замечает это и, когда сигнал снова хороший, один раз переподключает адаптер.

## Что нужно

- Linux с **NetworkManager**, `iproute2`, `iw`, `ping`, systemd.
- Телефон в режиме **USB-модема**: Android (драйверы `rndis_host`, `cdc_ncm`, `cdc_ether`) или iPhone (`ipheth`).
- Второй и третий каналы с того же телефона: **LAN** (роутер, который берёт интернет с точки доступа телефона) и/или **Wi‑Fi адаптер**, подключённый к точке доступа телефона напрямую. Работает с любым набором из двух или трёх каналов.

## Установка

```bash
git clone https://github.com/byha78/phone-multiwan.git
cd phone-multiwan
sudo bash install.sh
```

Установщик копирует службу в `/usr/local/sbin`, включает её автозапуск и задаёт две настройки ядра (`/etc/sysctl.d/90-multiwan.conf`).

**Подготовка NetworkManager (рекомендуется):**

```bash
# IPv6 на USB-модеме и Wi‑Fi адаптере выключить, иначе IPv6-трафик пойдёт мимо балансировки
nmcli con modify "<профиль USB-модема>"   ipv6.method disabled
nmcli con modify "<профиль Wi‑Fi адаптера>" ipv6.method disabled
# у LAN приоритет выше, чем у Wi‑Fi: на случай, если служба остановится
nmcli con modify "<профиль LAN>" ipv4.route-metric 500
```

## Проверка

```bash
journalctl -u multiwan-balance -f      # «Active: USB, LAN, Wi-Fi»
ip route show default proto 99         # общий маршрут и веса каналов
```

## Настройка

**Интерфейсы находятся автоматически:**
- **USB-модем:** по драйверу из `USB_DRIVERS`;
- **LAN:** первый проводной интерфейс со шлюзом, который не USB-модем. Подходит и сетевая карта компьютера, и виртуальная карта VM;
- **Wi‑Fi:** первый беспроводной интерфейс.

Если у вас есть USB-сетевая карта на драйвере `cdc_ether`, служба может принять её за телефон. В этом случае укажите интерфейс модема явно через `USB_IF`.

**Любой параметр** задаётся без правки скрипта:

```bash
sudo systemctl edit multiwan-balance
```
```ini
[Service]
Environment=WIFI_MODE=reserve
Environment=USB_WEIGHT=3
```

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `USB_IF` / `LAN_IF` / `WIFI_IF` | определяются сами | явно указать интерфейсы каналов |
| `USB_DRIVERS` | `rndis_host cdc_ncm cdc_ether ipheth` | по каким драйверам искать USB-модем |
| `WIFI_MODE` | `balance` | `balance` — Wi‑Fi третий канал; `reserve` — только если не работают USB и LAN |
| `USB_WEIGHT` / `LAN_WEIGHT` / `WIFI_WEIGHT` | 2 / 1 / 1 | доля новых соединений на каждом канале |
| `TARGETS` | `1.1.1.1 8.8.8.8` | куда пинговать при проверке канала |
| `PING_TIMEOUT` | 4 | сколько секунд ждать ответа: через телефон под нагрузкой задержка бывает большой |
| `INTERVAL` | 5 | период проверки, секунды |
| `FAILS_TO_DOWN` | 3 | столько неудачных проверок подряд — канал исключается |
| `REFRESH_SIGNAL` | −60 | сигнал (dBm), при котором вернувшийся Wi‑Fi адаптер переподключается |
| `REFRESH_CHECKS` | 3 | столько хороших проверок подряд перед переподключением |

**`WIFI_MODE`:** с Wi‑Fi в балансировке загрузка максимальна, но отдача немного ниже. Каналы толкаются за одну отдачу оператора и за эфир Wi‑Fi. Если отдача важнее, поставьте `reserve`.

## Удаление

```bash
sudo systemctl disable --now multiwan-balance
sudo rm /usr/local/sbin/multiwan-balance /etc/systemd/system/multiwan-balance.service /etc/sysctl.d/90-multiwan.conf
```

## Ограничения

- **Отдача не складывается.** Её ограничивает отдача сотовой сети (у автора ~30–57 Мбит/с), а разбивка по каналам даже немного вредит.
- **Одна закачка** идёт по одному каналу: максимум — скорость этого канала (~300 через USB).
- Раздача по USB и Wi‑Fi идёт через одну сотовую сеть, поэтому выше её скорости сумма не поднимется.
- Если роутер включён, но потерял связь с телефоном, служба заметит это за ~15–40 секунд.
